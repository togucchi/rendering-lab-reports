RENDERING LAB実験と検証の記録

002 · 内部解像度 100 / 75 / 50%

結果の要点

表示512×512を固定し、内部512×512、384×384、256×256の実描画を比較した。中庭・解析球・色の3実験、計9画像をGPU APIからreadbackした。全条件で不透明な画像、構図、上下方向、素材色、sRGB変換の検査が成功した。

50%では箱・球・外周の輪郭に段差と軟化が見える。大きな面の色と全体の構図は保たれる。75%にも輪郭差がある。これはこの固定シーン・512×512・t=0での観察で、視覚品質を一般に保証する合否基準ではない。低コントラストの大きな面には向く一方、小さな輪郭や斜線が重要な用途では50%の差が目立つ。文字・極細線・高周波テクスチャ・時間方向のちらつきは未検証であり、これらの破綻閾値を測定したとは主張しない。

方法・再現条件

  • ベースソース: fcbd6ec4a70e9a1022894d4bc673bea6e4cdaffc + この実験の変更。公開時の実際のsource commitはdemo/build-info.jsonに記録する。今回検証した変更済みtreeのソースsnapshot SHA256一覧を保存し、base commitだけを新実装の検証対象とは扱わない。
  • Rust1.99.0、wgpu30.0.1、Mesa25.0.7、llvmpipe LLVM19.1.7、GL、device type CPU。実機ハードウェアGPUではない。
  • 固定camera、t=0、同じWGSLとメッシュ。各条件は1scene viewport512×512。ブラウザーの2slot同時描画とは負荷構成が違う。
  • 内部寸法: 各表示viewport辺×scaleを整数に四捨五入、最小1。75%は各辺の比率でありピクセル数は56.25%、50%は25%。
  • 全倍率で独立color+Depth32Floatへ描画後、同じfullscreen triangleによるbilinear clampで表示へ拡大。100%にも同じ表示パスがある。
  • colorはRgba8UnormSrgb。samplingでlinearへdecodeして補間し、出力attachmentで一度encodeする。追加のgamma補正なし。
  • 各条件warmup10frame、sample30frame、3repeat。3scene×3scale×3repeat×30=810生サンプル。各repeatのwarmupはCSVから除外。
  • 順序はsceneごとに100→75→50、ランダム化なし。thermal・他プロセス負荷・CPUスケジューリング未統制。

再実行（出力は絶対パスにする）:

RENDERING_LAB_SCALE_OUTPUT="$PWD/evidence/native-scale" cargo test --locked -p rendering-core --test scale_smoke -- --ignored --nocapture

レポート画像・集計の再生成

native テストが生成した9枚の512×512 PPM、810行の生CSV、metadata.jsonから生成します。Python 3とPillowが必要です。カレントディレクトリに依存せず、相対入力パスはリポジトリルート基準です。

python3 scripts/build-scale-evidence.py --input evidence/native-scale
python3 scripts/build-scale-evidence.py --check

scene×scaleの9条件、各3repeat×30sample、display/internal寸法、重複や欠落、非有限タイミングを検証してから、9枚のlossless PNGと1536×550のラベル付き中庭比較画像、raw CSV・metadataのコピー、27行のsummaryを作成します。summaryは通常の中央値（偶数点の中央2値の平均）とnearest-rank p95、6桁丸め・末尾ゼロ省略です。既存のsummaryを入力に使いません。--check は一時ディレクトリで再生成し、再生成対象の13ファイルとバイト単位で比較します。別途保存した実行時の runs/source-snapshot.json は形式のみ検証し、再生成も上書きもしません。画像エンコード再現には同じPillow/zlib環境を使ってください。画像や生計測を捏造・再計測するコマンドではありません。

計測結果と限界

生CSV、repeat別summary CSV、条件・画質差JSONを保存した。summaryは各repeatの30点にmedian（偶数点は中央2値の平均）とnearest-rank p95を適用している。

中庭90点をまとめたnative completion wall中央値は100%=1.516ms、75%=1.449ms、50%=1.353ms。この実行のpooled中央値は低下したが、75%のrepeat中央値は1.414〜1.642msとばらつき、100%の1.470〜1.554msと重なる。ピクセル数に比例した高速化や、反復ごとの単調な改善は示されていない。これらはCPU software rasterizer上でencode/submitを呼び、queue完了までblocking waitするwall clock時間。GPU timestampでもブラウザーframe間隔でもない。値の差は固定の追加pass、CPU/driver overhead、queue待機、スケジューリング、順序効果を含む可能性がある。専用GPUやAndroid Chromeに外挿しない。

CSVはcpu_encode_submit_ms、native_queue_wait_ms、その合計のnative_queue_completion_wall_msを分ける。readback・画像保存・texture確保・pipeline作成を計測から除外。GPU時間・vsync・present・rAFは測っていない。

中庭の100%に対する全画像RGB byte-channel MAEは75%=0.412609、50%=0.654121。背景が大きいため全画像平均は輪郭劣化を過小評価する。MAEが小さいことを知覚的に同等という意味にしない。
