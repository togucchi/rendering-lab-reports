Instancing は draw 呼び出しをまとめますが、頂点数・fragment 数の削減や高速化は保証しません。CPU/rAF は A/B 合計です。同数・同条件の画質一致を確かめ、時間の比較には A/A 個別と A/A instanced を別 run で計測してください。

Transform / color は 48 bytes × 4096 = 196608 bytes を初期化時に一度だけ転送し、A/B で共有。各側の使用範囲は N × 48 bytes、個数変更や毎フレームの instance 再転送・CPU transform 更新はありません。初期化コストはこの計測に含みません。

まず両側で実験・カメラ・倍率を揃え、B の描画方式だけ変更。Prepass は depth 10 + color 10 draws。CPU/rAF 合計と画質を確認し、常に速くなるとは仮定しません。WGSL 編集時の prepass 比較は同じ不透明 coverage / depth と、vertex position の @invariant 指定が前提です。discard・fragment depth の変更は別途検証してください。

07 · 中庭 · Shadow mapping

A · Shadow inputs 512² · 1024 KiB depth · PCF 9 taps · shadow pass 1 draw
B · Shadow inputs 512² · 1024 KiB depth · PCF 9 taps · shadow pass 1 draw

中庭に細い柱 3 本と傾斜面を加え、light-space depth map から照合します。A/B の WGSL・カメラ・倍率を揃え、解像度・bias・PCF・光をひとつずつ変えて比較してください。全設定は JSON / CSV と PNG のファイル名に記録します。

Rasterizer constant bias は 0 / 2 / 65536、slope-scale は 0 / 1 / 8、clamp は 0。light depth pass の DepthBiasState に適用し、受光側の offset はありません。constant の単位は深度形式・実装依存で、正規化深度ではありません。「基準」は固定した比較条件で、native llvmpipe では PCF3/5 の縞状 acne を確認したアーティファクト例です。開始候補は512²・constant2・slope1・PCF1（硬い輪郭と階段状aliasingが残る）で、他GPUの最適値を保証しません。bias なしや基準条件の acne（自己遮蔽の縞）、過大 bias の peter-panning（影の浮き）、低解像度の aliasing（階段状の輪郭）を比較できます。

PCF は nearest comparison sampler で texel 中心の 1 / 9 / 25 回の比較を平均し、bilinear hardware PCF は使いません。輪郭を平均しますが、影マップの情報量は増えません。Depth debug は 16 回の二分探索比較で光から見た正規化深度を再構成した量子化表示で、raster bias を含みます。再構成区間は 1/65536 以下（framebuffer / 表示の量子化前）で、厳密な depth load や距離ではありません。visibility は可視率の確認用です。Depth debug は Off でも 16 比較、通常の Off は 0 比較です。影範囲外では sample 数が減り、custom WGSL の sample 数は保証しません。

Depth32Float は 4 bytes/texel。256² / 512² / 1024² は各側 256 KiB / 1 MiB / 4 MiB（driver overhead 等を除く）。On は毎フレーム shadow depth 1 + color 1 draw、Off は shadow pass と比較 sampling を省き color 1 draw。Depth map debug は Off でも影マップを再生成し、depth 1 + fullscreen debug 1 draw です。A/B の影マップは独立し、Off でも確保したメモリーは保持します。

CPU/rAF は A/B 全 pass の合計で、GPU 時間は未計測。影 On/Off のコスト比較は、同じ条件の A/A On と A/A Off を別 run で計測します。静止中も計測フレームごとに影マップを再生成します。bias 用の 9 パイプラインは WGSL コンパイル時に準備し、計測中は選択のみです。高解像度・広い PCF が常に良い／速いとは限りません。

B · SSAO inputs
AO サイズと追加メモリーは描画時に表示

SSAO は画面に見える形状から近接遮蔽を近似します。中庭・細い柱 3 本・傾斜面の固定 14 objects を使う独立実験で、shadow mapping / FlightHelmet PBR は合成しません。接触部、細い柱の輪郭、傾斜面、画面端で比較してください。

固定条件: world radius 0.7 · strength 1.3 · bias 0.03 · seed 17 · t = 0。SSAO はグローバル時間を無視します。A/B の WGSL・カメラ・内部描画倍率を揃え、samples / AO 解像度 / blur をひとつずつ変えると比較しやすくなります。Half プリセットは基準から AO 解像度だけを変えた 32 samples / Half / raw / Final / On です。プリセットは選んだ側の SSAO 設定だけを変更し、適用済みソースと編集中の変更を保持します。

Full / Half は AO target の各軸の倍率です。Half の AO は約 1/4 pixels（各軸 floor、最小 1）で、normal / world-position gbuffer は内部描画の full resolution を維持します。Bilateral blur は normal / position を参照して輪郭を保つ近似で、情報の欠落や halo、画面外の遮蔽を解決しません。AO は ambient 0.22 項だけに適用し、direct Lambert 0.78 項は変更しません。最終 AO の拡大は textureLoad による bilinear で、edge-aware upsampling ではないため、Half は輪郭に遮蔽がにじむ場合があります。AO-only の白は非遮蔽、暗部は遮蔽。Off + AO-only は白で、AO を計算しません。

追加 target は各側 RGBA16Float × 2（normal + world position、16 bytes/internal pixel）と RGBA8Unorm × 2（raw + blurred AO、8 bytes/AO pixel）。名目追加 bytes は 16 × internal pixels + 8 × AO pixels。既存 depth/color・alignment・driver overhead は除外します。blur Off でも両 AO targets を確保し、SSAO Off でも保持します。A/B の targets は独立です。

On は gbuffer 1 + AO 1 + final 1 pass/draw、blur 有効時は 1 pass/draw を追加。Off は final 1 pass/draw のみ。AO-only は final geometry の代わりに fullscreen 1 draw。さらに各側 upsample 1 draw を共通合成 pass に追加します。設定・固定条件・実サイズ・名目メモリー・pass/draw 数は JSON / CSV、PNG 名には全 SSAO 設定・固定条件を記録します。

CPU/rAF は A/B 全 pass の合計で、GPU 時間は未計測。コスト比較は同じ条件の A/A On と A/A Off を別 run で計測してください。AO/blur は enabled 時、静止中もフレームごとに更新します。設定変更時やサイズ固定直後のリソース再確保は記録 samples の前（warmup を含む）に行い、WGSL コンパイルも samples に含めません。画面上のノイズ・halo・接触部の消失と速度を分けて評価し、この画面だけから GPU 高速化率を推定しないでください。

09 · 中庭 · CPU Culling / Distance LOD

A · Culling / LOD 次の描画で実際の submitted draw list を表示
B · Culling / LOD 次の描画で実際の submitted draw list を表示

同じ中庭・不透明 geometry・光・カメラ経路を使い、A/B の CPU frustum culling と距離ベース LOD を独立に切り替えます。実験 05 の Instancing とは別の実験です。1 submitted object = 1 indexed draw で、draw batching は変更しません。固定カメラの選択は無効です。

時間の再生・停止・scrub で固定経路を再現します。同じ時刻・WGSL・倍率・50:50 の viewport で比較してください。Baseline と Cull only の画質一致を確認し、LOD only と Cull + LOD では輪郭の単純化と距離しきい値での popping を観察します。端を横切る objects や、床・壁に隠れた objects に注目してください。

固定 51 objects（中庭 10 + 外側の床 1 + 回転・非均等 scale の ellipsoid 40）。41 個の球 / ellipsoid は LOD 0/1/2 = 1840/440/100 triangles、箱・床は不変です。eye → world AABB 中心の距離が <12 / 12〜24 / ≥24 で LOD を選び、しきい値と等しい場合は低 detail 側です。ヒステリシスはなく、16〜20 s では中心球の距離 12 ± 0.04 を繰り返して popping を見せます。CPU 経路は 0〜20 s で clamp、ブラウザー再生は 20 s で巻き戻ります。

Bounds はローカル box の 8 corners を変換して囲む world AABB。WebGPU の clip depth 0〜w に対応した 6 正規化平面を使い、交差する bounds を保持し、world epsilon 0.0001 を適用します。固定 light = normalize(0.75, 1.25, 0.7)、shader 時刻は 0。グローバル時間はカメラだけに使います。

CPU frustum test は画面外を除外し、壁の後ろの遮蔽は検出しません。Occlusion culling は未実装です。visible / submitted は描画対象数で、実際に見えている pixel 数ではありません。tested は culling Off で 0。draws・triangles・LOD 0/1/2 は最後に実際に送信した draw list の値で、fragment 数や GPU 時間ではありません。

CPU/rAF は A/B と合成の合計で、GPU 時間は未計測。速度比較は A/A baseline、A/A cull only、A/A LOD only、A/A both を別 run で計測してください。固定時刻でも CPU tests / LOD 選択を毎フレーム行い、CPU encode に含めます。計測は操作をロックし、計測サイズの実 draw list を JSON / CSV に記録します。custom WGSL で頂点を bounds 外へ移動すると culling の保守性が失われる可能性があります。
