005 · glTF / metallic-roughness PBR 基準描画

結果と未完了条件

FlightHelmetの512px derivativeを、opaque metallic-roughness、GGX、height-correlated Smith、Schlick、接線空間normal mapで描画した。2カメラ×8条件＝16枚の実readbackと、各条件3repeat×10sample＝480点のnative release wall-timeを保存した。各条件の独立した2回のreadbackはA/A byte一致し、debug表示と各入力offはlit baselineから変化した。

Khronos公式viewerとの同一条件reference画像比較は未完了。cloud browserではWebGL 2が利用できずreference画像を取得できなかった。このレポートはIssue #6のreference比較要件を完了扱いにしない。内部A/A一致・数式テスト・入力toggleは独立rendererとの画質一致を証明しない。

実行環境はMesa llvmpipe / CPU software rasterizer / GL。以下の時間はCPU encode・queue submit・blocking queue waitを分けたnative wall clockであり、GPU timestamp、hardware GPU性能、Android実機性能、Webブラウザーのframe時間ではない。

一つずつ入力を外す

左上が全入力on。残りはbase-color texture、normal map、metallic-roughness textureを一つだけoffにしたもの。texture off時もglTF factorは残す。normal offはmesh normalを使う。camera、geometry、light、exposure、tone mapは固定する。

部位ごとの見方と既知の差

  • LensesMat: optional KHR_materials_transmission未対応。opaque core metallic-roughness fallbackを使う。レンズが不透明なのは既知の制限であり、透過referenceとの一致とは主張しない。
  • MetalPartsMat: metallicの反射は単一directional lightだけ。IBL・環境反射を持つreferenceに比べ、光が当たらない金属部が暗くなる可能性がある。今回その差をmatched imageで定量化していない。
  • LeatherPartsMat / RubberWoodMat / GlassPlasticMat / HoseMat: normal・roughness細部は512px化とmipで平滑化される。HoseはRubberWoodのimageを共有する。元の高解像度assetと同一texture条件ではない。
  • 接触部・凹部: cast shadow、IBL、indirect lightは未実装。ORM.rのocclusionはdirect lightに掛けない。暗部は主にN.Lによるもので、shadow mapの証拠ではない。
  • 全部位: linear計算の後、litだけ固定Reinhardとexposure 1。reference側のlight・environment・exposure・tone map・transmissionを揃えない比較には複数の交絡要因が残る。

llvmpipeでは描画そのものもCPU上で走り、submitやwaitにdriverの実行が含まれ得る。encodeだけを全CPU負荷とは呼ばない。encode + submit + waitがtotalであり、readback・asset準備・pipeline生成・固定buffer/target allocation・surface acquire/presentは含めない。nativeは1paneを直列submitし、Web A/Bの2pane・rAF・非同期queue・presentationと条件が異なる。

固定条件と実装範囲

  • Adapter: AdapterInfo { name: "llvmpipe (LLVM 19.1.7, 256 bits)", vendor: 65541, device: 0, device_type: Cpu, device_pci_bus_id: "", driver: "", driver_info: "4.5 (Core Profile) Mesa 25.0.7-2+deb13u1", backend: Gl, subgroup_min_size: 4, subgroup_max_size: 128, transient_saves_memory: None, limit_bucket: None }
  • Release profile。512×512 display/internal、100%、t=0、MSAAなし。6 scene draws / 1 scene pass、別のfullscreen display 1draw / 1pass。Depth32Float、Less、depth write。
  • Camera0 eye [0.7,0.5,1.1]、Camera1 eye [-0.8,0.55,-1.1]。共通target [0,0.25,0]、up [0,1,0]、aspect1でvertical FOV45°、near0.01/far10。
  • Direction toward light normalize([-0.5,0.8,1])、linear radiance [3,3,3]、exposure1。背景linear [0.025,0.037,0.052]。
  • Globalsはgroup0/binding0の80bytes。resolution[512,512]、time0、display_aspect1、column-major view_projection。PBR viewはgroup1、material/texturesはgroup2。
  • GGX distribution、height-correlated Smith visibility、Schlick Fresnel。dielectric F0=0.04、alpha=max(roughness²,0.0016)、metallicでdiffuseを減らす。
  • base-colorはsRGB textureとしてdecode、normal/ORMはlinear UNORM。ORM.G=perceptual roughness、ORM.B=metallic。factorを掛けてclamp。normalはtangent.wの符号とnormalScaleを使い、Y反転しない。
  • colorのmipはlinear-light、normalのmipは符号付きvector平均後normalize、ORMはdata-space平均。trilinear + REPEAT。lit出力のsRGB encodeはattachmentで行い、shader内で重ねてgamma補正しない。
  • loaderはこのcurated GLBのbounded opaque subset。一般的な任意glTFへの完全対応ではない。非identity transform、animation/skin/morph、external URI、unsupported required extension、非opaque material等を拒否する。

Asset provenanceと予算

KhronosGroup/glTF-Sample-Assets / Models/FlightHelmet、commit 4995a638c96dbc94376d3d6164e70fee3ac7f7a2 から作ったderivative。geometryは変更せず、55,392 vertices / 94,722 triangles、6meshes / 6materials / 15unique images。CC0-1.0、Gary Hsu: Conversion from Maya。source lockに元ファイルとprovenanceファイルのSHA256を保存し、prepared GLBとimage/mip reference hashesをmanifestに記録した。

  • GLB transfer 7,428,104 bytes、SHA256 e45247aaa51e168e80d65d1fc1d71538500f963ea30e868a5f7cef902e0ecbaf。
  • 512→1の10mip×15枚、RGBA8は1枚1,398,100bytes、合計20,971,500bytes。20MiB＝20,971,520bytesに対して20bytes残る。最大4個の1×1 fallbackを含めると20,971,516bytes。今回のassetで実測allocation対象texel bytesは20,971,500。
  • これは論理的なtexture texel storage。driver overhead、geometry、framebuffer/depth、CPU decoded copiesを含む総VRAM/RAM値ではない。A/B・同一semanticのshared imageを重複uploadしない。
  • manifestのmip hashはPython float64 preparation reference。Rust runtimeはf32で、量子化差は最大2/255が観測された。GPU-upload hashやbyte完全一致と表示しない。

builderはrelease profile、adapter、画像16条件・RGB512×512、差分14条件、CSV header・条件順序・sample数480・欠落/重複、有限非負timing・component合計を検証する。--checkは生成内容を一時領域で再生成しbyte比較する。--self-testの人工fixtureは検証用temporary directoryだけに作り、実測evidenceへ混ぜない。PNGのbyte再現は同一Pillow/zlib環境を使う。

native testはA/A、known-grayのsRGB出力経路（期待byte128/188、誤差≤1）、invalid WGSLのpipeline拒否を検証する。実際のWGSL helperをRgba16Float targetへ描画し、GGX・Smith・Schlick・ORM channel/factor・tangent handedness・normalScale・flat normal・back-face flipの数値fixtureを確認した（半精度量子化を含む絶対誤差<0.001）。これらはnative経路の検証であり、実ブラウザーのPBR操作やCore surface上のrollbackを実行した証拠ではない。Web状態遷移はJavaScript mockとcore transactionのコード確認で検証し、実browserのreload失敗後の画面保持・Android実行は未検証である。実行対象とraw evidenceのhashはworking-tree snapshotに記録する。公開済みbase commitだけを新実装の検証対象とは扱わない。
